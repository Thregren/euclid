# 构建与运行

本机未安装 Xcode，整套流程基于 CommandLineTools 的 Swift 工具链，无需 Xcode 即可开发和交付。

## 构建可双击运行的 App

```bash
./Scripts/build-app.sh
```

产物：`dist/尺规.app`（release 构建，ad-hoc 签名）。双击即可运行，也可以拖进「应用程序」。

调试构建更快：

```bash
CONFIG=debug ./Scripts/build-app.sh
```

## 运行自检

```bash
./Scripts/run-checks.sh                 # 投影、相机、路径拼装等纯计算检查
./Scripts/run-checks.sh /path/to/tiles  # 额外对真实数据集做嗅探与范围检查
./Scripts/run-checks.sh /path/to/x.tif  # 单幅影像体检：尺寸、坐标基准、范围、首屏耗时
```

单幅影像体检会打印像素尺寸、坐标基准（认出的 EPSG）、地面分辨率、经纬度范围、
原始比例层级与是否有内建概览，再按「原始比例」取一块、按首屏取一屏并计时；
`EUCLID_RASTER_DUMP=<目录>` 时还会把解出来的瓦片与整幅概览写成 PNG，便于目视核对。

本机没有 XCTest（随 Xcode 提供），因此自检是一个自带断言的可执行目标 `TileKitCheck`。
装上 Xcode 后可改用 `swift test` 的标准测试目标。

## 调试开关

全部通过环境变量开启，只在开发与核对时使用，正式使用不会有任何影响。
无人值守的核对（CI 式的「跑一遍、看日志与截图」）靠的就是下面这些开关。

| 环境变量 | 作用 |
| --- | --- |
| `EUCLID_TRACE=1` | 把数据集加载与选中流程打到 stderr |
| `EUCLID_TRACE_VIEW=1` | 每次重绘画布时打印层级、可见瓦片数、已载入／祖先兜底／缺片数、瓦片边长与中心坐标；在线层还会打基准偏移 |
| `EUCLID_FLOAT_WINDOW=1` | 让窗口保持置顶（截图/录屏用） |
| `EUCLID_DEMO_MEASUREMENT=1` | 打开数据集后生成示例测量（折线、多边形、圆与一段草稿），便于截图核对；这些示例**不会**写进测量存档，跑完不会覆盖用户自己的结果 |
| `EUCLID_DUMP_XLSX=/path/out.xlsx` | 自检程序把样例工作簿写到指定路径，便于用 Excel 复核 |

画布与出图：

| 环境变量 | 作用 |
| --- | --- |
| `EUCLID_DEBUG_SNAPSHOT=<目录>` | 配合下面的缩放脚本，逐帧把画布写成 `frame-NN.png`（离屏渲染，屏幕不在前台也能跑） |
| `EUCLID_DEBUG_ZOOM="i3,o5,i4"` | 启动后按脚本缩放：`i` 放大、`o` 缩小，字母后的数字是步数；结束时打印测量结果缓存的命中次数 |
| `EUCLID_DEBUG_EXPORT_VIEW=<png>` | 走一遍「导出当前视图」的合成路径并把成图写盘（含信息栏与比例尺），用来核对出图 |
| `EUCLID_DEBUG_APPEARANCE=dark\|light` | 强制浅色／深色外观，两种外观各截一次图核对对比度 |
| `EUCLID_DEBUG_WINDOW="x,y,w,h"` | 把主窗口摆到屏幕左上角 `x,y` 处并改成 `w×h`（窗口位置平时由系统的状态恢复决定），无人值守截图时只截窗口区域、不必截整屏 |
| `EUCLID_RASTER_TRACE=1` | 单幅影像取图时打印「世界坐标 → 像素区域 → 选的层级」，解压长度不对时也会报一行 |
| `EUCLID_RASTER_PYRAMID=<目录>` | 体检单幅影像时顺便真生成一套瓦片（512 / JPEG 85），并打印张数与用时 |
| `EUCLID_TM_TRACE=1` | 横轴墨卡托反算时打印中间量（核对与 PROJ 的差异时用） |
| `EUCLID_TIFF_TRACE=1` | Deflate 解压失败时打印读到的字节数与头部魔数 |

数据源与底图：

| 环境变量 | 作用 |
| --- | --- |
| `EUCLID_DEBUG_BASEMAP=<预设 id 或 URL 模板>` | 启动十几秒后切到指定的在线底图（`local` 表示切回本地数据） |
| `EUCLID_DEBUG_BASEMAP_KEY=<密钥>` | 配合上一条提供密钥 |
| `EUCLID_DEBUG_DATUM=wgs84\|gcj02\|bd09` | 指定底图的坐标基准 |
| `EUCLID_DEBUG_DATUM_SWITCH=<基准>` | 底图铺好之后再改一次基准，用来核对「只改基准也要重新装配图层」 |
| `EUCLID_DEBUG_LOCAL_OPACITY=0.5` | 设定本地影像的不透明度，做叠加对照截图时用 |
| `EUCLID_DEBUG_DOWNLOAD="模板\|西,南,东,北\|zmin\|zmax\|输出目录"` | 启动后按这组参数跑一次真实下载并把结果打到 stderr |
| `EUCLID_DEBUG_DOWNLOAD_SHEET=1` | 只把下载面板打开，便于截图核对 |

把本机的瓦片目录用一个只读 HTTP 服务当成在线底图，就能在断网的情况下核对在线链路
（叠加对齐、缩放不闪、出图都适用）：

```bash
cd /path/to/tiles && python3 -m http.server 8791 --bind 127.0.0.1
EUCLID_DEBUG_BASEMAP='http://127.0.0.1:8791/{z}/{x}/{y}.png' \
EUCLID_DEBUG_DATUM=gcj02 EUCLID_DEBUG_LOCAL_OPACITY=0.5 \
EUCLID_DEBUG_EXPORT_VIEW=/tmp/euclid-view.png ./dist/尺规.app/Contents/MacOS/Euclid
```

## 打开数据集

三种方式：

1. 启动后点工具栏「文件夹」或空态里的「选择文件夹…」，也可按 ⌘O；
2. 目录可以直接是数据集，也可以是装数据集的容器，应用会向下找三层；
3. 把文件夹拖到 Dock 图标上（应用已在运行时会直接打开）。

上次打开的目录会被记住，下次启动自动恢复。

## 首次运行的系统授权

瓦片放在「文稿」「桌面」「下载」等受保护目录时，macOS 会弹一次授权询问，点「允许」即可。
这是系统对用户目录的保护机制，与 App 本身无关。若希望完全免授权，可把瓦片放到不受保护的目录，
或改用软链接挂载到数据集目录（应用支持跟随符号链接）。

## 已知的行为约束

- **不要用位置参数启动**：`open -a 尺规 /path` 这类带路径的启动会被 AppKit 当成「打开文件」请求，
  SwiftUI 此时不会创建初始窗口。应用改为在运行中接收打开请求（Dock 拖放），启动路径只走「上次打开的目录」。
- `FileManager` 的 URL 版列目录接口不跟随路径末端的符号链接（会返回 `Not a directory`），
  数据层统一使用路径版接口。
